Exercise 5.1 — Histogram Bins: Same Data, Different Shapes

A histogram looks like a picture of the data, but its shape depends on choices the software makes for you: how many bins, where they start, and which bin gets a value that sits exactly on an edge.

1 Goal

By the end of this exercise you will be able to:

  1. read the counts behind a histogram instead of only looking at its shape;
  2. explain R's and NumPy's default bins and edge rules;
  3. make R and Python produce exactly the same histogram.

2 Predict first

Before running anything: what does each line return?

R

x <- c(1, 2, 2, 3, 3, 3, 4, 4, 5, 9)
h <- hist(x, plot = FALSE)
h$breaks
h$counts

Python

import numpy as np
x = np.array([1, 2, 2, 3, 3, 3, 4, 4, 5, 9])
counts, edges = np.histogram(x)     # what plt.hist(x) uses
print(counts)
print(edges)
Show the answer

R chooses about 5 bins (Sturges' rule) with "pretty" edges:

[1]  0  2  4  6  8 10
[1] 3 5 1 0 1

NumPy and plt.hist() use 10 equal bins from the minimum to the maximum:

[1 2 3 2 0 1 0 0 0 1]
[1.  1.8 2.6 3.4 4.2 5.  5.8 6.6 7.4 8.2 9. ]

Two different pictures of the same ten numbers.

3 The idea

Three choices define a histogram. Number of bins: R's hist() uses Sturges' rule (⌈log₂ n + 1⌉ = 5 here) and rounds the edges with pretty(); NumPy and matplotlib use 10 bins by default. Edges: R chooses round numbers; NumPy splits the range from min to max equally. Edge rule: R's bins are closed on the right, (0, 2], so the value 2 goes into the first bin; NumPy's are closed on the left, [2, 4), so 2 goes into the second.

With few observations, or with rounded data (ages, scores, Likert items), many values sit exactly on edges, and the edge rule can change the shape you see.

4 Your task

One histogram in both languages

Use the edges 0, 2, 4, 6, 8, 10 in both languages. First compare the counts with each language's default edge rule, then make R give exactly the same counts as NumPy.

R — starter code

x <- c(1, 2, 2, 3, 3, 3, 4, 4, 5, 9)

# Your code: hist(x, breaks = ..., plot = FALSE)$counts

Python — starter code

import numpy as np
x = np.array([1, 2, 2, 3, 3, 3, 4, 4, 5, 9])

# Your code: np.histogram(x, bins=...)

5 Hints

Hint 1

Both functions accept the edges directly: breaks = seq(0, 10, by = 2) in R, bins=[0, 2, 4, 6, 8, 10] in NumPy.

Hint 2

R's hist() has an argument right. Which value makes the bins left-closed, like NumPy's?

6 Solution

Show the solution

R

x <- c(1, 2, 2, 3, 3, 3, 4, 4, 5, 9)
b <- seq(0, 10, by = 2)

hist(x, breaks = b, plot = FALSE)$counts                 # (0,2], (2,4], ...
hist(x, breaks = b, right = FALSE, plot = FALSE)$counts  # [0,2), [2,4), ...
hist(x, breaks = b, right = FALSE)                       # draw it

Output

[1] 3 5 1 0 1
[1] 1 5 3 0 1

Python

import numpy as np
x = np.array([1, 2, 2, 3, 3, 3, 4, 4, 5, 9])

print(np.histogram(x, bins=[0, 2, 4, 6, 8, 10])[0])   # [0,2), [2,4), ..., [8,10]
# import matplotlib.pyplot as plt
# plt.hist(x, bins=[0, 2, 4, 6, 8, 10]); plt.show()

Output

[1 5 3 0 1]

With the same edges, the default rules still disagree: R puts the two 2s and the two 4s in the lower bin, NumPy in the upper one. right = FALSE makes R match NumPy.

7 Check yourself

Your answer is correct if

  • both languages give the counts 1 5 3 0 1 with edges 0, 2, …, 10;
  • you can explain why R's default gives 3 5 1 0 1 instead.

8 Why it matters

The bins are part of the result

Changing the bins can make a distribution look skewed, bimodal or flat. When a histogram supports a claim ("the scores are right-skewed"), set the edges yourself, state them in the caption, and check that the conclusion does not depend on them.
