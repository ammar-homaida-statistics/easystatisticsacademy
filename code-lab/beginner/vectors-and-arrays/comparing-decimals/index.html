Exercise 1.3 — Comparing Decimal Numbers Safely

Computers store most decimal numbers approximately. A value that prints as 0.3 may not be equal to 0.3, so an exact comparison can fail even when the mathematics is right.

1 Goal

By the end of this exercise you will be able to:

  1. explain why 0.1 + 0.2 == 0.3 is false in both R and Python;
  2. compare decimal numbers with a tolerance;
  3. find a value in a grid of decimal numbers without missing it.

2 Predict first

Before running anything: what does each line return?

R

0.1 + 0.2 == 0.3
isTRUE(all.equal(0.1 + 0.2, 0.3))

Python

import math
print(0.1 + 0.2 == 0.3)
print(math.isclose(0.1 + 0.2, 0.3))
Show the answer

Both languages give the same results, because both use the same 64-bit floating-point numbers:

FALSE
TRUE

(R prints [1] FALSE and [1] TRUE; Python prints False and True.) Printed with 17 significant digits, 0.1 + 0.2 is 0.30000000000000004.

3 The idea

A computer stores numbers in base 2. Just as 1/3 has no finite decimal expansion, 0.1 has no finite binary expansion, so it is stored as the nearest representable number. Small representation errors can add up, and the result of a calculation may differ from the "true" value in the 16th or 17th significant digit.

The fix is to ask whether two numbers are close enough rather than exactly equal. R provides all.equal() (default relative tolerance about 1.5 × 10−8); always wrap it in isTRUE() inside an if, because when the values differ it returns a text description instead of FALSE. Python provides math.isclose() and, for arrays, np.isclose().

4 Your task

Find 0.3 in a grid

A grid of values from 0 to 1 in steps of 0.1 is common in simulations (for example, a grid of correlation values or tuning parameters). Find the position of the value 0.3 in the grid. First try an exact comparison, then write a version that works.

R — starter code

grid <- seq(0, 1, by = 0.1)
grid
which(grid == 0.3)

# Your version: ...

Python — starter code

import numpy as np
grid = np.linspace(0, 1, 11)
print(grid)
print(np.where(grid == 0.3)[0])

# Your version: ...

5 Hints

Hint 1

Print the fourth element of the grid with all its digits: print(grid[4], digits = 17) in R, repr(grid[3]) in Python.

Hint 2

Replace "equal" by "the absolute difference is smaller than a tiny number", or use np.isclose().

6 Solution

Show the solution

R

grid <- seq(0, 1, by = 0.1)
which(grid == 0.3)                     # exact: finds nothing
print(grid[4], digits = 17)            # why
which(abs(grid - 0.3) < 1e-9)          # with a tolerance

Output

integer(0)
[1] 0.30000000000000004
[1] 4

Python

import numpy as np
grid = np.linspace(0, 1, 11)
print(np.where(grid == 0.3)[0])            # exact: finds nothing
print(repr(grid[3]))                       # why
print(np.where(np.isclose(grid, 0.3))[0])  # with a tolerance

Output

[]
np.float64(0.30000000000000004)
[3]

The position is 4 in R and 3 in Python: R counts from 1, Python from 0. It is the same element.

7 Check yourself

Your answer is correct if

  • the exact comparison finds nothing, and your version finds the fourth element of the grid (index 4 in R, 3 in Python);
  • your comparison uses a tolerance, not ==.

8 Why it matters

Silent failures in simulations and checks

Exact comparisons of decimal numbers break filters (selecting the rows for ρ = 0.3 from simulation results returns nothing), checks (probabilities that "should" sum to 1), and tests of your own functions. The code runs; it just gives an empty or wrong answer. Two rules prevent most of these problems: compare computed decimals with a tolerance, and, where possible, index grids by integers (the 4th value) rather than by decimal values.

9 Going further

  • Both: the default tolerances differ. all.equal() uses a relative tolerance of about 1.5 × 10−8; np.isclose() uses rtol = 1e-5 and atol = 1e-8. Find two numbers that one function calls equal and the other does not.
  • R: run all.equal(1, 1.1). Why must it be wrapped in isTRUE() inside if ()?
  • Python: why can np.isclose(a, 0) be misleading for very small numbers? (Look at atol.)
