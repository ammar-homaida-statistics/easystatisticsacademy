Exercise 3.3 — Joining Tables Without Losing or Duplicating Rows

1 Goal

By the end of this exercise you will be able to:

  1. predict the number of rows returned by a join;
  2. choose between inner and left joins;
  3. check a join by comparing row counts and totals before and after.

2 Predict first

Before running anything: what does each line return?

R

patients <- data.frame(id = c(1, 2, 3, 4), age = c(34, 52, 17, 41))
visits   <- data.frame(id = c(1, 1, 2, 5), cost = c(100, 150, 80, 60))
merge(patients, visits)

Python

import pandas as pd
patients = pd.DataFrame({"id": [1, 2, 3, 4], "age": [34, 52, 17, 41]})
visits   = pd.DataFrame({"id": [1, 1, 2, 5], "cost": [100, 150, 80, 60]})
print(pd.merge(patients, visits))
Show the answer

Both languages return the same three rows. Patients 3 and 4 (no visits) and the visit for id 5 (no patient record) have disappeared, and patient 1 now appears twice:

  id age cost
1  1  34  100
2  1  34  150
3  2  52   80

(pandas numbers the rows from 0.)

3 The idea

The default join in merge() (R) and pd.merge() (pandas) is an inner join: only IDs present in both tables are kept. A left join (all.x = TRUE in R, how="left" in pandas) keeps every row of the first table and fills missing values where there is no match.

When an ID appears several times in one table, each match produces a row, so patient-level variables are repeated. If you want one row per patient, summarise the visits per patient first, then join.

5 Hints

Hint 1

Step 1: total cost per id in visits (aggregate() in R, groupby().sum() in pandas). Step 2: left-join the totals onto patients.

Hint 2

After the join, missing costs are NA/NaN; replace them with 0. Then compare sum() of your cost column with sum(visits$cost).

6 Solution

Show the solution

R

patients <- data.frame(id = c(1, 2, 3, 4), age = c(34, 52, 17, 41))
visits   <- data.frame(id = c(1, 1, 2, 5), cost = c(100, 150, 80, 60))

tot <- aggregate(cost ~ id, data = visits, FUN = sum)
res <- merge(patients, tot, by = "id", all.x = TRUE)
res$cost[is.na(res$cost)] <- 0
res
c(sum(res$cost), sum(visits$cost))
setdiff(visits$id, patients$id)

Output

  id age cost
1  1  34  250
2  2  52   80
3  3  17    0
4  4  41    0
[1] 330 390
[1] 5

Python

import pandas as pd
patients = pd.DataFrame({"id": [1, 2, 3, 4], "age": [34, 52, 17, 41]})
visits   = pd.DataFrame({"id": [1, 1, 2, 5], "cost": [100, 150, 80, 60]})

tot = visits.groupby("id", as_index=False)["cost"].sum()
res = patients.merge(tot, on="id", how="left")
res["cost"] = res["cost"].fillna(0).astype(int)
print(res)
print(res["cost"].sum(), visits["cost"].sum())
print(sorted(set(visits["id"]) - set(patients["id"])))

Output

   id  age  cost
0   1   34   250
1   2   52    80
2   3   17     0
3   4   41     0
330 390
[5]

The totals differ by 60: the visit for id 5 has no patient record. That is not something to fix silently; it is a data-quality finding to report or investigate.

7 Check yourself

Your answer is correct if

  • your table has exactly 4 rows, one per patient, with costs 250, 80, 0 and 0;
  • its total is 330, against 390 for all visits; the 60 difference is the visit for id 5.

8 Why it matters

Joins change your sample size

An inner join can silently drop the people with no records (often exactly the ones you need to count), and duplicate keys can multiply rows and inflate sums and means. Two checks catch almost every join problem: compare the number of rows before and after, and compare a total (such as cost) before and after.
